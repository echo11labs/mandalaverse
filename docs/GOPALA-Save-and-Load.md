# Local settlement save/load

The Kathmandu settlement has one manual save slot. Click **Save** / **Load** in the top bar, or press **F5** / **F9**. **Shift+F9** loads the previous save backup. Loading replaces the active settlement and centres the camera on its workers/buildings. The saved pause and speed settings are restored.

Files are `user://saves/settlement.json` and `settlement.json.bak` (Godot's project user-data directory). Writing validates a temporary file, copies the previous primary to `.bak`, then renames the temporary file over the primary. A failed load keeps the active simulation and views intact; failures produce a HUD message. A failed backup copy or rename leaves the existing primary intact.

Schema 2 stores the resolved world seed/content fingerprint, cell scale/origin/bounds, exact fixed-clock state, ledger and individual store stock partitions, stable entity IDs/revisions and removed-ID tombstones, next command/task IDs, entity attributes/links, occupancy claims, gather tasks and construction tasks. This includes available/reserved source stock, carried goods, repeat gathering and all seven persistent collection roles and herding, reserved/delivered building materials, their origin-store allocations and labour progress. Typed JSON preserves StringName keys, integer IDs/quantities and exact 64-bit floats; quantities and nanoseconds are not rounded through JSON numbers. SHA-256 detects accidental payload corruption.

A save is captured outside service advancement and command-drain callbacks, after queued commands have drained. Load validates a detached simulation's types, IDs, references, balances, task ownership, reservation totals, store-to-aggregate stock equality, origin-store allocation totals, material requirements and claimed footprints before swapping authorities. Terrain navigation and moving routes are rebuilt from requested destinations; AStar caches and engine nodes are not authoritative saved data. All view/query adapters are rebuilt and HUD stock/tempo refreshed.

Compatibility is intentionally limited to the same Kathmandu world seed, grid/scale standard and admitted content/geography fingerprints. A changed seed, definition or standard is rejected; schema 1 is also rejected; there is no migration or cross-world terrain regeneration in this format. Decorative vegetation is regenerated by the scene's existing deterministic seed system. MVP need timers, health, consumption journals, homes, interrupted builder resumption, water refill counters and its scenario record are stored as entity attributes and validated before swapping. The MVP uses `user://saves/mvp.json` and `.bak`, separate from the landscape slot. Cattle, 4×4 pasture cells, finite grazing, physical feed cargo and ownership, production journals, milk sources and scenario progress also persist as validated plain records. There is no seasonal system or regional map-edit state yet; future systems must extend the format and tests. Camera transforms, selection and placement ghosts are presentation state and reset on load. The MVP scenario acceptance also saves and reloads halfway through the continuous fifteen-minute objective. Broader compatibility and G-028 save hardening remain.

`game/tests/run_save_tests.gd` is part of `python3 tools/verify.py`. It covers pre-pickup reservation, carried stone, blocked delivery then restored access, builder carrying, partial labour, cancelled construction with a carried refund, retained tombstones/ID counters, pause/speed/sub-tick state, exact numeric types, previous backup restoration, corrupted/unsupported saves, invalid references/negative stock/reservation imbalance, unchanged live state after failed loads and actual scene/view replacement. Movement uses physical routed ticks; these tests do not teleport workers to finish jobs.

Player cattle pasture assignments and movement state persist. Derived cattle waypoints are rebuilt from their saved physical positions; invalid pasture references and unsupported movement states are rejected. Production journals remain valid with crowding and fodder support.
