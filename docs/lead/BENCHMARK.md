# G1-12 benchmark protocol

Run `python3 tools/bench.py` from a clean committed checkout with the pinned `.tools` dependency available. It runs three vsync-off replays and one vsync-on reference at each of 1280×800 and 1920×1080. Each has 30 seconds of warm-up and 120 seconds of collection. Outputs are under reports/bench/: JSON, markdown, engine logs and two fixed-camera PNGs. `--output PATH` selects a separate directory. `--quick` is a short development replay and `--profile` is a separate instrumented diagnostic; neither qualifies as a baseline. `--smoke` is headless fixture/execution validation with no frame-performance claim, wired into verify.py.

The benchmark loads the actual MVP and preserves its renderer, herd, routes and snapshot observers. It disables only the simulation node's automatic physics callback, then calls the unchanged advance_ticks(1) on a wall-clock schedule. Existing 4x control means four logical ticks per real second. Each timed call includes snapshot observers and pending-command processing. When calls cannot sustain the schedule, the report records the actual sampled tick count and marks the run invalid; it never quietly slows the clock or discards the run.

The coordinator approved one fixture-initialization phase using existing registry and authorized stock APIs for finite sources, supplies, capacities and pre-existing completed buildings. It is confined to game/bench/fixture.gd. Initial amounts, seeds, roles, population, cattle and exceptional setup are recorded. Workers spawn on nearby open cells, one per preparation tick, followed by180 ordinary preparation ticks to dephase need trips; after which the approved one-time meal/drink due-tick staggering spreads forty offsets evenly across their unchanged policy intervals (1,4,...,118 ticks for120-tick intervals). Exact offsets are recorded; quantities and health are unchanged. This is before the timed30-second warm-up. Settler spawning, job and pasture assignment use commands. No replenishment or extra registry mutations occur during warm-up/collection. No production policy/service or world-scale changes are made. Completed fixture buildings are pre-existing records without new occupancy claims; this controlled gathering workload does not represent building a town from scratch.

Active means a live task, carried goods or job movement; mere role assignment and NEED supply trips are excluded. Each ten-second window records its strict per-tick minimum, and the whole-run minimum is reported. Below36 of40 makes the run invalid. Invalid runs remain visible and cannot establish a <=5% regression comparison. They are evidence of a workload/performance limitation, not a passing acceptance benchmark.

Frame samples come from the real RenderingServer.frame_post_draw signal. They include main-thread stalls and presentation, not just GPU work. Capture readback occurs before the timed warm-up/collection; it is excluded. Both fixed camera positions are captured from the same initialized prepared fixture, then the camera returns to camp and switches to pasture halfway through collection. Captures are pre-timing reference views, not screenshots of the final simulated state. The runtime window stays above other windows to avoid macOS occlusion stopping draw signals; the open editor is not controlled. Record display refresh, adapter, renderer, engine, machine model/memory, power and thermal availability. Other user applications are left intact; their CPU load is recorded.

Budgets: frame p95 <=16.7ms at1280×800, <=20ms at1920×1080; full tick-call p95 <=4ms. Compare future valid runs only against the matching clean-checkout fixture, renderer, hardware and camera protocol; <=5% p95 regression budget. Three-run p95 population variance and range are reported. A baseline run is not an exported-build measurement.

For hotspots, `--profile` uses Godot's local script profiler in a separate replay; inspect the accumulated function table at shutdown and frame tables around slow ticks. Inclusive totals overlap and must not be added. Profiling changes timings, so these values do not replace the uninstrumented baseline.

## Suggestions

Keep the editor and other heavy work quiescent by agreement with Devendra, keep the Mac on power, and record repeat-run variance. If budgets fail, profile the existing snapshot/registry/job paths before adding vegetation or AI addons. Never reduce the workload, hide invalid runs or raise budgets to present a passing result.
