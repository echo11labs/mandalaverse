# Local settlement camera, rendering and planning grid

The default orthographic view spans 40 metres vertically and centres on the current workers and building view positions. Home recomputes those positions and fits them with an eight-metre margin, expanding the span when actors spread out. Camera panning, zooming and regional overview remain available; Home does not run every frame or interrupt exploration.

The settlement grid uses the existing two-metre cell contract, with borders half a cell away from cell centres. A 2x2 definition occupies a 4x4-metre plot, including working space around compact imported structures. The grid covers the same 48x48 logical bounds as occupancy and snapping, appears automatically during placement, and follows the manual grid toggle otherwise. The preview is grounded and outlines the exact transformed footprint. Placement rays query the terrain layer, so a tree or building collider cannot shift the chosen ground cell.

The rendered ground now has 256 independently culled chunks of 32x32 quads. The complete reference mesh remains for terrain physics, and the shared material keeps the geographic survey continuous across chunks. Every triangle, winding, normal and vertex colour is retained. Ground height for actors, sources, grid and previews interpolates the actual rendered triangle, including its diagonal; this avoids drift between full-resolution elevation data and the sampled surface. The camera uses the same visible surface height.

At a span of 500 metres or less, decorative MultiMeshes use a camera window with 25 metres of base padding plus tilt-dependent reach for a 40-metre canopy bound. Nearby coarse source batches are divided into 100-metre tiles using measured model bounds, preserving transforms, colors, custom data, materials and population. Unneeded visual tiles are hidden; a bounded cache of 128 source groups reuses them during panning (active groups may exceed the limit). Wider views restore the original coarse batches. Camera-local shadow reach replaces the old 100-kilometre shadow range. No authoritative actor, source stock, task, reservation, inventory or simulation processing is culled. Whole-world source meshes and terrain physics are still resident; this is rendering optimization, not disk streaming or a memory reduction claim.

The real-renderer `local-view-tests` stage checks grid borders, terrain triangle preservation/shared overlays, current actor focus, rotated ghost snapping/grounding, view switching, native MultiMesh transform/data preservation, cache reuse and unchanged inventories. The normal verification gate also reruns collection, delivery and construction suites. The dummy renderer cannot read serialized MultiMesh transforms, so scenery subdivision is disabled in headless runs; the gate explicitly runs its relevant tests with a real renderer.

`reports/manual/local-render-before.json` and `local-render-after.json` contain matched 40-metre camera samples using the Apple M4 Pro Compatibility renderer. Submitted primitive/draw counters are direct evidence; the short average frame-time sample can be affected by other running editor/game processes and is not a broad performance acceptance test. Screenshot reviews: `local-camera-after.png` and `settlement-grid-detail.png`.
